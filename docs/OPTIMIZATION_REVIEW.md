# VLAA 运行体验与批量处理审查

审查日期：2026-11-11。范围为通用视觉工作流、标注复核与保存、数据集同步、批量导出、运行调度和前端呈现。以下是代码与离线测试能够支持的结论；不代表已验证未接入服务商的视觉识别质量。

## 本次完成

| 问题 | 实现与效果 |
| --- | --- |
| 自动标注没有独立进度，容易把“待审”误解为没有生成标注 | 在运行页集中呈现自动步骤百分比、已生成并检查张数、当前图片与步骤、人工确认数量 |
| 等待 LLM 时无法判断已等多久 | 展示当前步骤时间和累计自动处理时间，读取数据库记录，刷新页面不会从零开始 |
| 无剩余时间信息 | 本批完成至少两张后，按最近十张的实际处理时间估计；不把人工等待算进速度，不把重试重复计为完成 |
| 异常状态容易出现虚假倒计时 | 失败、取消、断开连接、样本不足、耗时超出样本时说明原因，不承诺完成时刻 |
| 每两秒拉取完整运行与复核负载 | 新增轻量运行摘要；轮询不读取复核掩膜，省略历史标注负载，事件最多一百条；保留完整详情接口 |
| 批量中某步骤只完成一张也显示为完成 | 显示已完成和尚未到此步的张数，不再将部分完成渲染为整步完成 |
| 大批图片难找待办、一次渲染过多行 | 按待复核、失败和处理中筛选；显示原文件名，每次展开五十张 |
| 页面完成或正在编辑时仍持续轮询 | 完成、取消、编辑与后台页面暂停轮询，保存和返回时更新 |

本机现有单图运行的实际响应测量：完整运行详情为 798,246 字节，轻量摘要为 23,908 字节，减少约 97%。这是该运行的实测结果，不是所有数据集的固定压缩比例。

## 建议的后续顺序

| 优先级 | 代码依据与影响 | 建议 |
| --- | --- | --- |
| 高：批量导出任务化 | `backend/app/workflow/batch_exports.py` 在单次 HTTP 调用中逐图生成 JSON、PNG 和 ZIP；`BatchExportPanel.tsx` 只能等待完整结果。大批量导出难以了解进度或恢复 | 建立可恢复的导出任务，持久化成功/失败项，显示逐图进度并支持重试失败项 |
| 高：有界并发调度 | `backend/app/workflow/runtime.py` 在一个调度线程中逐次调用 `tick`，视觉 HTTP 请求会占用这个线程；一个慢请求影响其他运行 | 对远端 API 增加小规模、可配置并发；继续串行保护本地 GPU，保留请求预算、事务与取消隔离。并发变更后同步调整 ETA 算法 |
| 中：历史记录分页与自动刷新 | `list_runs` 默认只返回最近 50 条，最多 200 条，尚无游标翻页；历史列表目前手动刷新 | 新增按项目/状态/日期过滤与游标分页，只对活跃记录自动刷新 |
| 中：前端按页面加载 | `App.tsx` 静态导入标注、训练、模型和工作流页面。本次生产构建主 JS 约 850 kB，gzip 约 257 kB | 按路由延迟加载大页面与画布模块，保留明确的加载和失败重试提示 |
| 中：取消说明与请求截止时间 | `vision/provider.py` 的取消需等当前 HTTP 请求返回或超时，超时为网络操作超时；并不是点击后立即中断远端计算 | 页面说明“正在结束当前请求”；后续引入整体请求截止时间与取消令牌，避免误认为远端已停止计费 |
| 中：新手设置层次 | 工作流设置同时展示方案、模型、类别、预算和输出设置，内容仍较长 | 保留常用项在主界面，将预算、坐标协议、修复策略收进可展开的高级设置，并提供任务准备检查 |

## 时间与进度的口径

自动步骤百分比属于步骤完成比例，不是 LLM token 生成比例，也不是标注准确率。当前调度为串行执行，因此 ETA 依据本批完成图片的自动处理时间计算；样本仅使用计时完整的图片，累计时间排除人工关卡。因服务重启而中断的尝试缺乏准确停机时间，不计入测速样本。

已排除的图片不计为成功标注；全部有效任务结束后可能低于 100%。已确认数据仍须通过现有整图确认与快照规则，进度显示不会改变审核条件。

## 验证方法

新增测试覆盖已完成步骤去重、重试成本、检测任务跳过分割、单图无 ETA、批量 ETA、长请求、人工等待、取消、排除、轻量摘要与完整详情兼容、批量筛选、轮询暂停和部分完成状态。沿用已有标注保存、数据集同步、快照与训练回归测试；界面另在本地浏览器检查。

验证记录：后端全量 578 项通过，随后补充的大批量边界、自定义路由测试与工作流回归共 34 项通过；前端全量 195 项通过，随后运行页与进度组件的 13 项针对性测试通过，生产构建通过。浏览器检查了实际待复核运行、失败筛选和约 400 CSS 像素宽度的布局。构建仍提示主 JS 包较大，已列入后续优化。

此次不以真实收费视觉服务运行来评估模型质量。塔体、卫星图等真实批量数据仍需按任务类别验证识别效果和耗时分布。
